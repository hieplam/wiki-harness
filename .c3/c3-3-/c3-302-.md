## Goal

Hold every fixed-content (MANAGED-class) source file a wiki instance receives byte-for-byte, with
no per-instance variable substitution, re-copied verbatim on every `init` and every `upgrade`.

## Parent Fit

| Field | Value |

| Category | Foundation — c3-210 (init) and c3-211 (upgrade) both copy this component's files verbatim; nothing inside c3-3 depends on it |
| Depends on | ref-ownership-classes (this component is the MANAGED class named there) |
| Depended on by | c3-210 (init, step 7: copy verbatim, and step 9: seed the 4 CLAUDE.md stubs); c3-211 (upgrade, step 9: overwrite every managed-role path with the new version's bytes, including the 4 CLAUDE.md paths) |

## Purpose

Own `templates/sources.AGENTS.md`, `templates/wiki.AGENTS.md`, `templates/sources.cards.AGENTS.md`
(mechanism only — schema pointer, id scheme, byte-matched `CARD_KEY` worked example, `UNFILED`
rule; the trust table and per-origin recipes are cut out to `c3-303`'s `recipes.md`), and
`templates/CLAUDE.root.tmpl` / `templates/CLAUDE.nested.tmpl` (both the literal single line
`@AGENTS.md`; `CLAUDE.nested.tmpl` is seeded once per nested dir — `sources/`, `sources/cards/`,
`wiki/`). Non-goal: this component's files are never instance-editable in the sense `c3-303`'s
are — an owner's local edit to a MANAGED file is drift, not a deliberate SEED-then-own transition,
and only becomes permanent through `upgrade --adopt-drift`.
